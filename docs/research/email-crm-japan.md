# 対内実験調査：Claude Code / Codex + Gmail で「日本式・季節の挨拶 CRM」

作成日: 2026-09-03　対象: 自分用（公開リポジトリのため個人情報は書かない）

## 1. 結論（先に）

- **成立する。** Gmail MCP（検索・スレッド取得・下書き作成・ラベル）と Google Calendar MCP（祝日カレンダー読み取り・予定作成）だけで、「誰に・いつ・どの挨拶を出すか」の判定から下書き作成までを Claude Code / Codex に任せられる。送信は人が押す設計にしておけば安全。
- **今回の実験で実際に動いたもの**: 送信済みメールから日本の取引先を洗い出し（過去1年で日本語ビジネスメールのスレッド 24 件）、自分の過去の年始メール（2025-01-01 送信）から文体を学習し、残暑見舞いの窓口内（立秋 8/7〜白露前日 9/6）に **Gmail 下書きを1通生成**（宛先は自分、送信していない）。
- **足りないもの**: 連絡先マスタ（Google Contacts の MCP が無い）、送信予約（Gmail の「送信日時を設定」は API から不可）、二十四節気の自動取得（毎年手で `seasons.json` を更新）。

## 2. 現状のメールボックスから分かったこと

| 項目 | 結果 |
|---|---|
| 送信済み | 169 通 / 88 スレッド |
| 過去1年の日本語ビジネススレッド（「お世話になっております」等） | 24 スレッド |
| 過去に自分が送った季節の挨拶 | 新年の挨拶 1 通（2025-01-01）。暑中・残暑・寒中・年末は 0 |
| 相手の業種 | 大手 SIer、事業会社、VC、自治体、研究機関、スタートアップ（すべて日本） |
| カレンダー | 「日本の祝日」カレンダー購読済み（Asia/Tokyo）。敬老の日・大晦日・節分などの「祭日」も入っている |

つまり「関係はあるが、季節の挨拶で関係を維持する運用は一切していない」状態。大姑（日本で独立開業している医師）の運用は、ここを埋めるもの。

## 3. 日本の習慣：出すべき挨拶と窓口

窓口は `crm/seasons.json` に機械可読で入れてある。要点だけ。

| 挨拶 | 窓口（JST） | 注意 |
|---|---|---|
| 年賀・新年のご挨拶 | 1/1〜1/7（関西 1/15）。理想は元日午前 | 喪中の相手には出さない → 寒中見舞い。忌み言葉を避ける |
| 寒中見舞い | 1/8〜立春前日（2/3） | 祝いの言葉を使わない。喪中の相手・年賀を出しそびれた相手 |
| 余寒見舞い | 立春〜2月末 | 出しそびれ救済のみ |
| お中元 | 関東 7/1〜7/15、関西 7/15〜8/15 | 過ぎたら表書きを暑中御見舞→残暑御見舞へ。医師・公務員には贈らない |
| 暑中見舞い | 小暑（7/7）〜立秋前日（8/6） | 梅雨明け前は早い。**立秋を過ぎたら残暑** |
| 残暑見舞い | 立秋（8/7）〜8月末、最遅で白露前日（9/6） | 暑中と両方は出さない。もらったら返す |
| 敬老の日 | 9月第3月曜 | 高齢の患者・恩師で喜ばれる場合だけ |
| お歳暮 | 12/1〜12/20（関東は 11/20〜可） | 過ぎたら御年賀・寒中御見舞 |
| 年末のご挨拶 | 12/15〜12/28（仕事納め） | 喪中でも可。「良いお年を」を避ける。休診案内を兼ねられる |
| 誕生日・開業記念日 | 当日 | 周年（1・3・5・10・20）は必須 |
| 訃報・入院・昇進 | 知った当日〜3日 | 訃報後はその相手の `mourning_until` を設定して年賀を止める |

二十四節気は年ごとに1日ずれる。2026 年は立春 2/4、小暑 7/7、立秋 8/7、白露 9/7（国立天文台 暦計算室で確認）。2027 年の夏の節気は未確認としてフラグを付けてある。

医院の運用で特有なもの: 休診案内（年末年始・GW・お盆）は患者全員に一斉、個別文面は不要。患者への年賀は出す医院と出さない医院があるので、Tier で分ける。

## 4. 設計

```
crm/
  seasons.json          挨拶の窓口・ルール・節気テーブル・件名
  contacts.example.json 連絡先スキーマ（サンプル）。本番は contacts.local.json（gitignore）
  templates/*.md        日本語テンプレ 16 種（{{name}} {{personal_line}} 等を埋める）
  due.mjs               「今日誰に何を出すか」を副作用なしで計算（node 22）
.claude/skills/jp-seasonal-crm/SKILL.md
                        Claude Code / Codex がこの CRM を回す手順（下書きのみ、送信禁止）
```

連絡先の主なフィールド: `tier`（A=全文個別、B=テンプレ+一言、C=出さない）、`region`（関東/関西でお中元の窓口が変わる）、`occasions`（この相手に出す挨拶の集合）、`dates.birthday/anniversary`、`mourning_until`（喪中）、`personal_notes`、`history`（何年に何を出したか）。

1回の実行の流れ（skill に記載）:
1. `node crm/due.mjs --lookahead 7 --json` で候補を出す
2. Gmail `search_threads` で同じ相手・同じ窓口に既に送っていないか確認
3. `personal_notes` と直近スレッドの件名から「個別の一言」を作る（Tier A は全文書き直し）
4. テンプレを埋めて `create_draft`、ラベル `CRM/季節挨拶` を付ける
5. `history` に追記し、作った下書きの一覧だけをユーザーに報告

定期実行は Routine（毎週月曜 09:00 JST）で十分。窓口は最短でも1週間あるため。

## 5. 実験ログ

| 手順 | 結果 |
|---|---|
| Gmail ラベル一覧 | 取得可。ユーザーラベルは未作成 |
| `in:sent` で季節挨拶キーワード検索 | 0 件（運用していない） |
| `in:sent newer_than:1y` 日本語ビジネス検索 | 24 スレッド。相手のメール・会社が取れる → 連絡先マスタの初期化に使える |
| 過去の新年メール本文取得 | 可。丁寧体・「！」を控えめに・具体的な感謝を1行、という文体が分かった |
| 日本の祝日カレンダー読み取り | 可。2026-09〜2027-02 の祝日・祭日 16 件 |
| `crm/due.mjs` を 2026-09-03 / 08-10 / 10-01 / 12-20 / 2027-01-02 で実行 | 残暑・年末・年賀・開院10周年・喪中→寒中の切り替えが期待どおり |
| `create_draft`（残暑見舞い、宛先は自分） | 成功。draft id 取得。送信していない |
| `create_label`（`CRM/季節挨拶`、親ラベル自動作成）| 成功。ラベル ID 取得。初回はパラメータ名 `name` で失敗、正しくは `displayName` |
| `label_message` で下書きにラベル付与 | 成功（空オブジェクトが正常応答） |

## 6. リスクと対策

- **誤送信**: MCP に `send_message` があるので、skill で「送信禁止・下書きのみ」を明記。将来は permission 設定で `mcp__Gmail__send_message` を deny に入れる。
- **個人情報の流出**: 公開リポジトリ。連絡先は `contacts.local.json` のみ、レポートは件数と業種まで。
- **窓口の誤り**: 立秋を過ぎた「暑中」は相手に「常識がない」と受け取られる。`due.mjs` が節気テーブルから判定するので、毎年2月に `seasons.json` を更新する運用をカレンダーに入れる。
- **喪中**: 喪中はがきを受け取ったら手で `mourning_until` を入れる必要がある。Gmail の受信メールから「喪中」を検索して候補を出す自動化は次の段階。
- **文面の画一化**: テンプレそのままでは日本の受け手にはすぐ分かる。Tier A は必ず全文個別、Tier B でも「一言」を過去スレッドから生成する。

## 7. 次にやること

1. `crm/contacts.local.json` を送信済みメールから初期化する（skill の手順 2 を一度全件で回す）。宛先ごとに Tier と occasions を手で決める。
2. 年末（12/15〜）に本番で年末のご挨拶を回し、1/1 に年賀を回す。今年の残暑見舞いは窓口が 9/6 までなので、出すなら今週。
3. Routine を登録（毎週月曜 09:00 JST）。
4. 大姑の運用をヒアリングして `seasons.json` に「医院向け」の項目（休診案内の文面、患者への年賀の可否、お歳暮辞退の定型文）を追加する。
5. Codex 側でも同じ skill が使えるよう `AGENTS.md` に skill へのポインタを置く。
